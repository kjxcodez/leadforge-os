# LeadForge OS: Post-Phase 13 Findings Matrix

| ID | Severity | Type | Area | Finding | Evidence | Risk | Recommended Action |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **DELAY-01** | **CRITICAL** | BUG | Scheduler / Workflow | Delay steps yield `wait`, update MongoDB to `WAITING`, but **never update SQLite** `sequence_executions`. Scheduler only scans SQLite. | `automation.ts:1237-1270`, `event-bridge.ts:90-118`, `scheduler.ts:380-398` | Multi-step campaigns with delay intervals stall permanently and never resume. | Update SQLite `sequence_executions` directly or via ProjectionService whenever an execution enters `WAITING`. |
| **SCHED-02** | **CRITICAL** | BUG | Scheduler | SQLite query compares ISO-8601 string (`YYYY-MM-DDTHH:MM:SS.sssZ`) with SQLite `datetime('now')` (`YYYY-MM-DD HH:MM:SS`). Because ASCII `'T'` > `' '`, string comparison fails for same-day delays. | `scheduler.ts:388`: `se.nextExecutionAt <= datetime('now')` | Due executions scheduled for today are invisible to the scheduler until midnight UTC. | Wrap column in `datetime(se.nextExecutionAt) <= datetime('now')` or compare unix epoch timestamps. |
| **INBOUND-03**| **CRITICAL** | BUG | Inbound / Reply | Race window: Reply arrives while outbound delivery is still `SENDING` (`finalizeDelivery` in progress). Thread/header/contact queries fail. Reply marked `UNMATCHED` with permanent idempotency key. | `reconciliation.service.ts:616-670`, `email.service.ts:570-583` | Reply is permanently lost; contact never marked `REPLIED`; campaign continues sending follow-ups to contact who replied. | Defer unmatched inbound replies with a 2-minute reconciliation lease window before marking terminal UNMATCHED. |
| **THROTTLE-04**| **CRITICAL** | BUG | Rate Limiting / Engine | Mailbox 429 cooldown sets `rateLimitedUntil` in MongoDB. Next steps yield `wait` with `retrySameStep: true`. Intersects with **DELAY-01**. | `email.service.ts:658-661`, `automation.ts:1618-1628` | A single Gmail 429 response permanently halts all active campaigns using that mailbox. | Fix DELAY-01 and implement dedicated mailbox backoff queue in Scheduler rather than stalling individual executions. |
| **TPL-05** | **HIGH** | INCOMPLETE FEATURE | Templates | `findVersion(templateId, version)` exists in repository and contracts, but is **never exposed in API routes or SDK**. Worker always fetches latest mutable template. | `email-template.repository.ts:62-102`, `automation.ts:1484-1498` | Editing a template mid-campaign alters email content for in-flight contacts; breaks immutable delivery lineage. | Expose `GET /templates/:id/versions/:version` in API router, SDK, and use pinned version in `handleSendEmailStep`. |
| **FINGERPRINT-06**| **HIGH** | DOCUMENTATION DRIFT | Composition | SDK computes fingerprint over tracking-injected HTML and attachment checksums. API computes fingerprint over raw HTML and omits attachments entirely. | `variable-resolver.ts:572-582` vs `email.service.ts:289-298` | SDK preview fingerprint and delivery ledger fingerprint never match; audit trail verification fails. | Unify fingerprint calculation by using SDK's canonical `composeOutboundMessage` inside `EmailService`. |
| **PAUSE-07** | **HIGH** | ARCHITECTURAL GAP | Campaigns / UI | UI "Pause Campaign" button calls `campaigns:update` in `crm.ts`, not `campaigns:pause`. Only updates campaign row; does NOT cancel running jobs or pause executions. | `CampaignsScreen.tsx:1097`, `crm.ts:395-411` vs `campaigns-ipc.ts:451-497` | Pausing a campaign from the desktop UI does not stop background workers; emails continue sending until campaign finishes. | Route UI pause action to `campaigns:pause` IPC, and propagate execution pauses to MongoDB via SDK. |
| **ENROLL-08** | **HIGH** | PRODUCT GAP | Audience / Contacts | Enrollment idempotency only checks `WHERE campaignId = ? AND contactId = ?`. Cross-campaign check is missing. | `campaigns-ipc.ts:67-76`, `email.service.ts:256` | Same contact enrolled in multiple campaigns gets spammed with simultaneous conflicting emails. | Add workspace-level outreach exclusivity check: prevent enrolling contact if already active in another campaign. |
| **RESUME-09** | **HIGH** | ARCHITECTURAL GAP | Campaigns / UI | There is NO `campaigns:resume` IPC handler in the desktop main process. UI calls `campaigns:update` with status `ACTIVE`. | `campaigns-ipc.ts`, `CampaignsScreen.tsx:1112` | Resuming a campaign does not unpause or reschedule previously paused sequence executions. | Implement `campaigns:resume` IPC channel to unpause executions and enqueue due workflow jobs. |
| **RETRY-LINEAGE-10**| **HIGH** | BUG | Outreach / Delivery | In-process throttle retry in `automation.ts` omits `templateId`, `templateVersion`, and `variablesSnapshot` from the retry `sendEmail` call. | `automation.ts:1630-1644` | If an email is throttled for 5 seconds and succeeds on retry, its delivery record has NULL template and variables lineage. | Pass `templateId`, `templateVersion`, and `variablesSnapshot` into the retry `sendEmail` payload. |
| **SCHED-CRASH-11**| **HIGH** | BUG | Scheduler / Recovery | Scheduler updates SQLite execution `WAITING -> RUNNING` via CAS before `sdk.jobs.create`. If crash or network failure occurs, execution is orphaned. | `scheduler.ts:401-428` | Execution is marked `RUNNING` in SQLite with no corresponding job in MongoDB; will never run again. | Wrap execution recovery in a 2-phase claim or scan for `RUNNING` executions without active jobs on startup. |
| **STARTUP-RECOVERY-12**| **HIGH** | OBSERVABILITY GAP | Operations / Scheduler | Application startup recovery sweeps MongoDB `jobs`, but does NOT sweep or reset SQLite `sequence_executions` stuck in `RUNNING`. | `scheduler.ts:160-220` | Orphaned executions from a crash remain stuck in "Running" state indefinitely in the desktop UI. | Add startup reconciliation query in SQLite: reset `RUNNING` executions without active jobs back to `WAITING` or `FAILED`. |
| **UNSUPPRESS-13**| **HIGH** | BUG | Suppression | `SuppressionRepository.unsuppress()` removes record from MongoDB `suppressions`, but does not delete from SQLite `suppressions` or restore `ContactModel.status`. | `suppression.repository.ts`, `email.service.ts:240-254` | Un-suppressing an email in the admin console fails to allow sends because local cache or contact status still blocks. | Synchronize un-suppression to SQLite and provide option to reset `ContactModel.status` to `NEW` or `CONTACTED`. |
| **SEC-EMAIL-14**| **MEDIUM** | INCOMPLETE FEATURE | Inbound / Contacts | Inbound reply from an address not listed in `ContactModel.additionalEmails` fails sender correlation completely. | `reconciliation.service.ts:655-660` | Inbound replies from personal/alternate addresses are marked `UNMATCHED`, campaign attribution is lost. | Add manual reply reconciliation UI in Operations Center to link unmatched replies to contacts. |
| **TPL-DELETE-15**| **MEDIUM** | BUG | Templates / Outreach | Deleting an active template causes subsequent steps in waiting campaigns to crash and fail executions immediately. | `automation.ts:1484-1505` | Deleting a template ruins running campaigns even though older versions are archived in MongoDB. | Fallback to `TemplateVersionModel` when active template is deleted, or block template deletion while campaigns reference it. |
| **DISCONNECT-16**| **MEDIUM** | PRODUCT GAP | Email Accounts | Disconnecting a Google account leaves attached campaigns active. Queued jobs fail one by one with `MAILBOX_NOT_ACTIVE`. | `email-account.service.ts:320-335`, `email.service.ts:270` | Failures pollute error logs, consume retries, and lower campaign health scores unnecessarily. | Automatically transition campaigns using the disconnected mailbox to `PAUSED` with operator notification. |
| **ENGINE-DUPLICATION-17**| **MEDIUM** | TECHNICAL DEBT | Architecture | Monorepo has `@leadforge/workflow-engine` package, but outreach campaigns run on an ad-hoc 2,627-line engine in `automation.ts`. | `packages/workflow-engine` vs `apps/desktop/src/main/workers/plugins/automation.ts` | Duplicated execution logic, diverging semantics, maintenance overhead, and false test confidence. | Consolidate campaign execution onto `@leadforge/workflow-engine` or formally retire the unused package. |
| **CIRCULAR-DEP-18**| **MEDIUM** | TECHNICAL DEBT | Architecture | Circular dependencies in `apps/desktop`: 8 worker plugins circular with `worker-host.ts`; `scheduler` <-> `projection-service` <-> `logger`. | `pnpm doctor` / `depcruise` output | Harder module isolation, unpredictable load order, and bundling fragility. | Decouple worker plugin interface into a standalone types package and invert dependency injection. |
| **DRIFT-STOP-19**| **MEDIUM** | ARCHITECTURAL GAP | Consistency | Stopping a campaign via API cascades cancellations in MongoDB, but does not notify SQLite projection until a manual sync occurs. | `campaign.service.ts:69-99` | Desktop UI shows stale `ACTIVE` status and running counts after API stop. | Emit event bridge signal or WebSocket notification to rehydrate campaign projection upon API mutation. |
| **ANALYTICS-FALLBACK-20**| **LOW** | ARCHITECTURAL GAP | Analytics | SQLite `email_deliveries` is only populated when a user visits the delivery logs UI (`outreach:list-deliveries`). | `outreach.ts:356-380`, `analytics-ipc.ts:18` | Offline analytics fallback in desktop is almost always empty or severely outdated. | Project delivery summaries during `reconcileJobOutcome` or document that analytics requires API connectivity. |
| **LINT-MARKETING-21**| **LOW** | TECHNICAL DEBT | Codebase Health | 31 errors and 65 warnings in `apps/marketing` (setState in useEffect, unescaped entities, explicit any). | `pnpm doctor` / ESLint flat config output | Code hygiene failure; prevents clean `pnpm doctor` pass in CI. | Fix React hooks usage, escape entities, and replace `any` in marketing application. |
| **FORMAT-PRETTIER-22**| **LOW** | TECHNICAL DEBT | Codebase Health | 49 files failing Prettier formatting check across scripts and packages. | `pnpm doctor` / Prettier output | Repo hygiene failure. | Run repository-wide `prettier --write` during next maintenance phase. |
| **TENANT-ISOLATION-23**| **INFORMATIONAL** | ARCHITECTURAL GAP | Multi-Tenancy | Workspace isolation is strictly maintained across API repositories via `workspaceId` filters, with zero cross-tenant leakage. | `apps/api/src/repositories/*` | Verified safe. | Maintain rigorous workspace scoping invariants in all future endpoints. |
| **SEND-GATE-24**| **INFORMATIONAL** | ARCHITECTURAL GAP | Delivery | Send-time suppression and qualification safety gates function correctly and prevent suppressed sends. | `email.service.ts:240-254` | Verified safe. | Preserve current multi-gate validation architecture. |
