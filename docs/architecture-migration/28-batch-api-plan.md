# LeadForge OS — Batch API Implementation Plan

## 1. Executive Summary & Problem Definition

In the legacy local-first architecture, background workers (such as the Playwright Google Maps scraper or LinkedIn enricher) performed thousands of rapid individual row inserts directly into local SQLite files via synchronous `db.prepare().run()` calls.

> [!WARNING]
> If these individual local database writes are converted 1-to-1 into individual HTTP REST calls (`POST /companies`, `POST /contacts`), the system will suffer from:
> 1. Severe HTTP connection overhead and socket exhaustion.
> 2. Vercel serverless function invocation limits and latency degradation.
> 3. Atlas free-tier connection pool saturation and write throttling.

To guarantee high throughput without degrading performance, we introduce **Canonical Batch APIs** using MongoDB's native `bulkWrite()` and `insertMany({ ordered: false })`.

## 3. Standard Batch Execution Lifecycle

```text
  Worker Process (e.g. Scraper accumulates 50 companies)
         │
         ▼
  SdkClient: sdk.companies.createBulk(companyDtos)
         │
         ▼ HTTP POST /api/v1/companies/bulk
  Hono Gateway (apps/api)
         │
         ├─► 1. Authenticate session & verify workspace access
         ├─► 2. Validate array size (1 <= length <= MAX_BATCH_SIZE)
         ├─► 3. Validate each item against Zod schema (collecting errors)
         │
         ▼
  CompanyRepository.bulkUpsert(workspaceId, validItems)
         │
         ▼ MongoDB Atlas (bulkWrite with ordered: false)
  Collection.bulkWrite([
    {
      updateOne: {
        filter: { _id: item.id, workspaceId },
        update: { $set: item },
        upsert: true
      }
    },
    ...
  ], { ordered: false })
         │
         ▼
  Compile BulkWriteResult:
  {
    success: true,
    totalRequested: 50,
    insertedCount: 45,
    updatedCount: 5,
    failedCount: 0,
    errors: []
  }
         │
         ▼ (HTTP 200 OK or HTTP 207 Multi-Status)
  Worker updates local SQLite cache with persisted authoritative records
```

## 4. Endpoint Specifications

### 4.1 `POST /companies/bulk`
* **Path:** `/api/v1/companies/bulk`
* **Method:** `POST`
* **Max Batch Size:** 100 items
* **Payload Structure:**
  ```typescript
  export const bulkCompanySchema = z.object({
    companies: z.array(companySchema.omit({ createdAt: true, updatedAt: true })).min(1).max(100)
  });
  ```
* **Deduplication & Conflict Handling:**
  - Matches on `_id` (string UUID generated by worker).
  - If a company with the same `workspaceId` and `domain` already exists with a different ID, the API merges fields or reports a duplicate conflict without aborting other valid items in the batch.
* **MongoDB Operation:**
  ```typescript
  const operations = companies.map(c => ({
    updateOne: {
      filter: { _id: c.id, workspaceId },
      update: { $set: { ...c, workspaceId } },
      upsert: true
    }
  }));
  const result = await CompanyModel.bulkWrite(operations, { ordered: false });
  ```
* **Response Shape:**
  ```typescript
  {
    success: true,
    meta: {
      total: 100,
      upserted: 92,
      modified: 8,
      failed: 0
    },
    items: [{ id: "...", status: "persisted" }]
  }
  ```

---

### 4.2 `POST /contacts/bulk`
* **Path:** `/api/v1/contacts/bulk`
* **Max Batch Size:** 100 items
* **Payload:** Array of contacts containing explicit string `id` and `companyId`.
* **Semantics:** Upserts on `{ workspaceId, email }` or inserts on `{ _id }`.

---

### 4.3 `POST /intelligence-evidence/bulk`
* **Path:** `/api/v1/intelligence-evidence/bulk`
* **Max Batch Size:** 200 items (lightweight text facts)
* **MongoDB Operation:**
  ```typescript
  await IntelligenceEvidenceModel.insertMany(evidenceItems, { ordered: false });
  ```
* **Duplicate Behavior:** In case of duplicate content hashes, duplicate items throw error 11000 and are skipped silently (`ordered: false`), allowing all unique items to commit.

---

### 4.4 `POST /discovery-results/bulk`
* **Path:** `/api/v1/discovery-results/bulk`
* **Max Batch Size:** 100 items
* **Purpose:** Allows scraper to persist an entire page of Google Maps results in a single roundtrip.
* **Atomic Linkage:** Automatically creates or links `CompanyDiscoveryRunModel` records to maintain provenance.

---

### 4.5 `POST /jobs/bulk`
* **Path:** `/api/v1/jobs/bulk`
* **Max Batch Size:** 100 items
* **Purpose:** Dispatches workflow DAG steps or enqueues hundreds of contact enrichment tasks in a single operation.
* **Idempotency:** Evaluates `idempotencyKey` per item. Existing idempotency keys are returned as existing jobs rather than re-enqueued.

## 5. Partial Failure & Error Handling

Batch endpoints implement standard partial-failure semantics:

```text
┌─────────────────────────┬────────────────────────────────────────────────────────────┐
│ Failure Category        │ Handling Strategy                                          │
├─────────────────────────┼────────────────────────────────────────────────────────────┤
│ **Payload Validation**  │ If any item fails schema validation, the API returns       │
│ (Malformed Zod input)   │ HTTP 400 Bad Request detailing invalid index items.        │
├─────────────────────────┼────────────────────────────────────────────────────────────┤
│ **Duplicate Key (11000)│ `ordered: false` allows all non-conflicting documents to  │
│ (Unique constraint)**   │ succeed. Conflicted items are logged in the `errors` array.│
├─────────────────────────┼────────────────────────────────────────────────────────────┤
│ **Workspace Mismatch**  │ Items carrying an invalid `workspaceId` are rejected       │
│                         │ during validation before reaching the database.            │
├─────────────────────────┼────────────────────────────────────────────────────────────┤
│ **Network Abort**       │ SdkClient retries the entire batch with exponential backoff│
│                         │ using identical item IDs (naturally idempotent).           │
└─────────────────────────┴────────────────────────────────────────────────────────────┘
```

## 6. SdkClient Batch Integration

In `packages/sdk/src/modules/companies.ts`:

```typescript
export class CompaniesModule {
  // ...
  public async createBulk(companies: CompanyDto[]): Promise<BulkWriteResponse> {
    // Automatically chunk large arrays into batches of 100
    const CHUNK_SIZE = 100;
    const results: BulkWriteResponse[] = [];

    for (let i = 0; i < companies.length; i += CHUNK_SIZE) {
      const chunk = companies.slice(i, i + CHUNK_SIZE);
      const res = await this.httpClient.post<BulkWriteResponse>(
        '/companies/bulk',
        { companies: chunk }
      );
      results.push(res);
    }
    return mergeBulkResults(results);
  }
}
```
